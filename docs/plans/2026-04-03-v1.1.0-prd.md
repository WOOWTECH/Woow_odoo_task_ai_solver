## 1. Executive Summary

This maintenance release addresses 12 issues identified during a comprehensive code audit of the `project_ai_solver` module. The changes span security hardening, architecture improvements, performance optimization, and frontend quality. All changes follow the Kaizen principle of incremental, independently testable improvements.

**Key outcomes:**
- Eliminated fragile magic-string channel identification
- Removed raw SQL in favor of ORM-only patterns
- Added cursor-based pagination to message history
- Hardened portal security with rate limiting and tighter record rules
- Fixed memory leaks in frontend components
- Added defense-in-depth XSS mitigation

## 3. Solution Design

### 3.1 Architecture: Replace Magic String with Boolean Field

**Before:** `self.name.startswith('Task Chat:')` in `discuss_channel.py`
**After:** `is_task_chat = fields.Boolean(default=False)` on `discuss.channel`

This field is set to `True` during channel creation in `project_task.py` and checked in the `message_post` override. The security record rule in `security.xml` now includes `('is_task_chat', '=', True)` to scope portal access exclusively to task chat channels.

### 3.2 Security: ORM-Only Attachment Creation

**Before:**
```python
attachment = request.env['ir.attachment'].sudo().create({...})
request.env.cr.execute("UPDATE ir_attachment SET create_uid = %s WHERE id = %s", ...)
```

**After:**
```python
attachment = request.env['ir.attachment'].with_user(
    request.env.user
).sudo().create({...})
```

`with_user()` sets the user context so `create_uid` is correctly set to the portal user. `sudo()` only bypasses ACL checks, not the user context.

### 3.3 Reliability: Savepoint for Race Condition Handling

**Before:** `cr.rollback()` after `IntegrityError` — rolls back entire transaction
**After:** `with request.env.cr.savepoint():` context manager — isolates the failure

```python
try:
    with request.env.cr.savepoint():
        channel.write({
            'channel_member_ids': [Command.create({'partner_id': partner.id})]
        })
except IntegrityError:
    _logger.debug("Portal user already a member (race condition)")
```

### 3.4 Performance: Cursor-Based Pagination

Added `before_date` parameter and `has_more` flag to the `/chat/history` endpoint. The server fetches `limit + 1` records, detects overflow, and returns messages in ascending chronological order.

Both frontend widgets (OWL backend and legacy portal) now support a "Load older messages" button.

### 3.5 Security: Rate Limiting

In-memory per-user, per-endpoint rate limiter:

| Endpoint | Limit | Window |
|----------|-------|--------|
| `/chat/history` | 60 requests | 60 seconds |
| `/chat/post` | 30 requests | 60 seconds |
| `/chat/upload` | 20 requests | 60 seconds |

### 3.6 Frontend: Memory Leak Fix & XSS Defense

- **OWL component:** Added `onWillUnmount` hook to clear `_busDebounce` timeout
- **Portal widget:** Changed from `setInterval` to chained `setTimeout` with exponential backoff on errors (3s → 6s → 12s → 24s → 48s → 60s cap)
- **XSS defense:** `<script>` tag stripping as defense-in-depth on `msg.body` before innerHTML insertion

### 3.7 UX: UserError on Empty Task

Enabling chat on a task with no `user_ids` and no `partner_id` now raises `UserError` with a clear message instead of silently returning an empty recordset.

### 3.8 Security: Scoped Record Rules

Portal record rule domain changed from:
```
[('channel_member_ids.partner_id', '=', user.partner_id.id), ('channel_type', '=', 'group')]
```
To:
```
[('channel_member_ids.partner_id', '=', user.partner_id.id), ('channel_type', '=', 'group'), ('is_task_chat', '=', True)]
```

### 7.3 Data Migration

Existing channels with `name LIKE 'Task Chat:%'` and `channel_type='group'` need `is_task_chat=True` set. This happens automatically via the new field default and the module update process. For existing channels created before the update:

```sql
-- Run once after module update if existing channels exist
UPDATE discuss_channel
SET is_task_chat = TRUE
WHERE name LIKE 'Task Chat:%'
  AND channel_type = 'group'
  AND is_task_chat IS NOT TRUE;
```

### 7.4 Rollback Plan

1. Restore previous module files
2. Run `odoo -u project_ai_solver --stop-after-init`
3. The `is_task_chat` field will remain in the database but be unused

## 8. Known Limitations

1. **Rate limiting is in-memory.** In multi-worker deployments, each worker maintains its own rate limit state. For clustered deployments, consider Redis-backed rate limiting.

2. **`bus.bus._sendone` loop.** Odoo 18 CE does not expose `_sendmany`. Each channel member receives an individual bus notification. This is acceptable for typical task chat channels (2-5 members) but could be inefficient for channels with many members.

3. **Polling-based portal chat.** The portal widget uses HTTP polling (3s fast / 15s slow) rather than WebSocket/long-poll. This is intentional — portal users don't have access to Odoo's bus long-polling infrastructure.

4. **No file type validation server-side.** The server accepts any file type up to the size limit. File type restrictions are client-side only. Consider adding server-side MIME type validation for hardened deployments.

5. **Channel orphan state after deletion.** When a channel is deleted directly (not via task), `chat_enabled` remains `True` while `channel_id` becomes `False` (due to `ondelete='set null'`). Re-enabling chat correctly creates a new channel. This is a known edge case — in normal usage, channels are never deleted independently. (Verified in v3 Round 8.)

6. **Rate limiter per-user, not per-session.** The rate limiter tracks by `user_id`, so multiple browser sessions from the same user share a single rate limit window. This is by design for security but means legitimate multi-tab usage may hit limits earlier.

7. **Path traversal filenames stored as-is.** Odoo's `ir.attachment` stores filenames as metadata only — actual file data is stored as base64 in the database, not on the filesystem. Path traversal filenames like `../../../etc/passwd` are harmless but could be confusing in UIs. Consider sanitizing filenames in a future release.
